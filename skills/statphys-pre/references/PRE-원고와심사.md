# PRE 원고와 심사 — 투고 판단, 구조, figure, referee 대응

**주의**: APS의 논문 유형·서식·정책은 바뀐다. 투고 관련 구체 규정(분량 제한, Letters 형식,
데이터 공개 정책, 서식 파일)은 조언하기 전에 `web_search` 또는 APS 공식 페이지로 확인한다.
아래는 바뀌지 않는 **내용상의 기준**에 초점을 둔다.

## 1. "PRE에 낼 만한가" 판단

PRE는 통계물리·비선형동역학·soft matter·생물물리·전산물리·복잡계 네트워크를 포괄하는
넓은 저널이지만, 넓다는 것이 기준이 낮다는 뜻은 아니다. 다음을 먼저 자문한다.

1. **무엇이 새로운가를 한 문장으로.** "새 모형을 제안했다"는 새로움이 아니다.
   새로운 것은 보통 (i) 새로운 보편적 거동, (ii) 기존 이론의 반례, (iii) 정량적으로
   더 정확한 이론, (iv) 이전에 풀 수 없던 계의 해, (v) 실험/데이터와의 새로운 정량 연결 중 하나다.
2. **결과가 모형 세부에 얼마나 의존하나.** 세부 의존적이면 범위를 좁혀 다른 저널을 고려한다.
3. **정량적 주장에 오차가 붙어 있나.** 임계점·지수·전이 차수 주장에 오차와 크기 사다리가
   없으면 심사 전에 되돌아온다.
4. **선행연구와의 비교가 지수/임계점 수준에서 되어 있나.**
5. 결과의 성격에 따라 저널을 고른다 — 상세 지도는 `references/저널-지형도.md`.
   요약하면 기술적으로 완결된 정량 결과는 PRE, 물리학 일반이 놀랄 단순한 메커니즘은 PRL/PRX,
   재현·음성·방법 비교는 PR Research, 학제간 실데이터는 PLOS Complex Systems·EPJ Data Science다.
   어느 쪽을 노리는지 사용자와 **먼저** 합의하고 그에 맞춰 서론의 강도를 정한다.

## 2. 원고 구조 템플릿 (Regular Article)

```
I.   INTRODUCTION
     - 문제와 왜 중요한가 (2~3문단)
     - 선행연구와 남은 간극 (구체적으로: 무엇이 측정되지 않았나)
     - 이 논문이 하는 일 + 핵심 결과 미리 말하기 (1문단)
II.  MODEL
     - 정의를 재현 가능하게: 상태, 전이율, 업데이트 순서, 경계조건, 파라미터
     - 알려진 극한(mean-field, 특수 파라미터)에서 무엇으로 환원되는지
III. ANALYTICAL TREATMENT
     - mean-field/HMF/생성함수 → 임계점 예측, d_c, 유효한 영역 명시
IV.  NUMERICAL RESULTS
     - 방법(알고리즘·크기·오차) → 임계점 결정 → FSS → 지수와 collapse
V.   DISCUSSION
     - universality 판정, 기존 class와의 비교, 예측 가능한 실험/데이터
     - 한계: 어떤 가정이 결과를 바꿀 수 있는지 스스로 적는다
VI.  CONCLUSION (짧게)
APPENDIX: 유도 세부, 알고리즘 세부, 추가 크기·파라미터 확인
```

서론의 마지막 문단에서 결과를 미리 말하는 것(result-forward)이 물리 저널의 관례다.
"우리는 ~을 조사했다"가 아니라 "우리는 ~임을 보인다"로 쓴다.

## 3. Figure

- 폭은 단일 컬럼(약 8.6 cm) 기준으로 설계하고, 그 크기로 축소했을 때 축 라벨과 범례가
  읽히는지 실제로 확인한다. 최종 인쇄 크기에서 글자가 본문 글자보다 작으면 안 된다.
- 로그 축이면 데이터 범위가 최소 1.5~2 decade는 되어야 멱함수 주장이 성립한다.
  한 decade짜리 직선으로 지수를 주장하지 않는다.
- FSS 그림은 **원본과 collapse를 나란히** 싣는다(보통 main + inset).
  collapse 축 라벨에 쓴 지수 값은 캡션에 오차와 함께 반복한다.
- 오차막대가 심볼보다 작으면 캡션에 "error bars are smaller than the symbols"라고 적는다.
  오차막대가 아예 없는 정량 그림은 referee의 표준 지적 대상이다.
- 색에만 의존하지 않는다(흑백 인쇄·색각 이상). 선 종류·심볼로도 구분되게 한다.
- 캡션은 그림만 보고 이해되도록: 무엇을, 어떤 크기·파라미터로, 무엇으로 평균했고,
  오차는 어떻게 냈는지.

## 4. 수치 보고 관례

- 임계점·지수는 `0.6300(4)` 형태(괄호 = 마지막 자리의 1σ)로 쓴다.
  통계오차와 계통오차를 구분할 수 있으면 `0.6300(4)(9)`처럼 나누고 본문에서 설명한다.
- 유효숫자를 오차보다 많이 쓰지 않는다. `ν = 0.6300 ± 0.05`는 자기모순이다.
- 문헌값과 비교할 때는 **오차 범위 겹침**으로 말한다. "일치한다"가 아니라
  "2σ 안에서 일치한다"가 정확한 표현이다.
- 지수 비(β/ν)로 측정한 것을 β로 환산해 보고할 때는 ν의 오차 전파를 포함한다.

## 5. 전형적 reject 사유 (원고 쓰기 전에 스스로 점검)

1. 기존 모형의 사소한 변형 + 시뮬레이션, 새로운 보편적 결론 없음.
2. 단일 크기 결과로 상전이·임계점·차수를 주장.
3. 오차 산정 부재 또는 naive 오차(자기상관 무시).
4. 로그–로그 직선만으로 멱함수·scale-free 주장.
5. mean-field 결과를 저차원/이질적 계에 그대로 적용.
6. 선행연구 누락, 특히 같은 결론이 이미 나와 있는 경우.
7. 모형 정의가 모호해 재현 불가(업데이트 순서·노이즈 규약 누락).
8. 주장과 데이터의 불일치 — 초록의 단정이 본문 그림보다 강함.

## 6. Referee report 대응

- **응답 구조**: 각 지적을 그대로 인용 → 무엇을 바꿨는지 → 원고의 어느 줄인지.
  바꾸지 않을 때는 이유를 데이터·문헌으로 댄다. 감정적 반박은 결과를 나쁘게만 한다.
- **가장 흔한 요구 셋**: (i) 더 큰 크기 / 더 많은 통계, (ii) 오차 산정 방법 명시,
  (iii) 기존 class와의 비교. 셋 다 미리 넣어 두면 심사 왕복이 줄어든다.
- 지적이 오해에서 비롯됐다고 판단되면, 오해를 유발한 원고의 문장을 고치는 것이
  "referee가 잘못 읽었다"고 쓰는 것보다 항상 낫다.
- 추가 계산을 요구받았는데 자원이 부족하면, 할 수 있는 규모까지의 경향과 외삽을 제시하고
  한계를 명시한다. 침묵하거나 질문을 회피하면 reject 사유가 된다.

## 7. 초록 쓰기

네 문장 골격: (1) 무엇을 다루는 계·문제인가, (2) 무엇을 했는가(방법 한 줄),
(3) **핵심 정량 결과**(임계점/지수/전이 차수를 숫자로), (4) 왜 중요한가·어디에 일반화되는가.
"we study"로 시작해 결과 없이 끝나는 초록은 편집자 단계에서 거절될 위험이 가장 크다.
