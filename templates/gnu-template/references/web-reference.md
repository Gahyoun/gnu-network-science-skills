# GNU 웹페이지 디자인 참고

웹 제작은 사용자가 2026-10-04에 제공한 경상국립대학교 **대학 시각 이미지(VI)** 하위 페이지 화면을 기본 참고로 삼는다. 홍보용 랜딩페이지보다 대학의 정보 안내 페이지에 가까운 구조로 만들며 사진 없는 구성을 기본으로 한다. 이 문서는 해당 화면의 구성에서 가져올 요소와 작은 교내 웹페이지에 적용하는 방법을 정리한 제작 지침이다.

공식 참고 페이지: [대학 시각 이미지(VI) 기본요소](https://www.gnu.ac.kr/main/cm/cntnts/cntntsView.do?cntntsId=1198&mi=1369). 공식 색상·서체·자산과 이 도구의 제안값은 [근거 문서](source-notes.md)에서 구분한다. 개인이 제공한 스크린샷 원본은 이 배포 폴더에 포함하지 않는다.

## 화면에서 가져오는 구조

1. **넓은 흰 헤더.** 왼쪽에 공식 로고와 운영 주체를 두고, 실제 페이지에 필요한 메뉴를 가로로 배치한다. 메뉴와 제목은 굵은 산세리프를 사용한다. 넓은 여백과 검정 글자가 먼저 보이도록 한다.
2. **사진 없는 짙은 현재 위치 띠.** 흰 헤더 바로 아래에 짙은 바탕의 현재 위치 행을 둔다. 기본형에 캠퍼스 항공사진이나 사진 배너를 넣지 않는다. 사용자가 사진 배너를 명시적으로 요청하고 실제 로컬 이미지를 제공한 경우에만 선택적으로 추가한다.
3. **왼쪽의 큰 실제 페이지 제목.** 배너 뒤에 충분한 흰 여백을 두고 페이지명을 배치한다. 제목 오른쪽에는 동작하는 인쇄 등 필요한 도구만 둔다. 별도의 광고 카피나 후크 문구를 붙이지 않는다.
4. **넓고 평평한 직사각형 하위 메뉴.** 참고 화면은 기본요소·슬로건·응용요소의 세 메뉴를 한 행에 배치한다. 작은 사이트에는 해당 콘텐츠의 실제 섹션명을 사용한다. 선택 항목은 청색 면과 흰 글자, 나머지는 흰 면·회색 테두리·회색 글자로 구분한다. 메뉴 개수를 세 개로 강제하지 않는다.
5. **항목명과 설명이 나란히 놓이는 본문 행.** 왼쪽의 굵은 항목명과 오른쪽의 설명·목록·표를 두 열로 배치한다. 큰 회색 선과 여백으로 정보 구획을 나누고 내용이 필요한 경우에만 원본 그림이나 자료를 붙인다.
6. **넓은 흰 공간과 단순한 하단 정보.** 내용을 모두 카드에 담지 않고 문단·행·표를 중심으로 배치한다. 하단에는 실제 운영 주체·문의처·관련 자료를 둔다.

```text
공식 로고 · 실제 운영 주체             실제 메뉴
──────────────────────────────────────────────
홈 · 운영 주체 · 현재 페이지       ← 짙은 현재 위치 띠

실제 페이지 제목                         인쇄

[ 소개             ][ 일정             ][ 자료·문의        ]

소개                 본문 문단
                     이어지는 설명

일정                 일시 · 내용 · 장소 표

자료·문의            실제 자료 링크 / 실제 문의처
──────────────────────────────────────────────
실제 운영 주체 · 연락처
```

## 작은 교내 웹페이지로 적용하기

대학 전체 메뉴·MY GNU·로그인·언어 선택·검색을 그대로 붙이지 않는다. 연구실이면 소개·일정·자료, 행사면 행사 안내·일정·참여 방법처럼 실제 운영 범위에 맞춘다. 이미 구현된 검색·신청 기능이 있을 때만 해당 조작을 넣는다. 예시의 인쇄 버튼은 브라우저 인쇄를 실행하고, 하위 메뉴는 실제 본문 섹션으로 이동한다.

현재 위치는 `nav`와 목록으로 구성하고 현재 페이지에 `aria-current="page"`를 표시한다. 페이지 내 이동 메뉴는 `a href="#section-id"`를 사용한다. 화면을 실제로 전환하지 않는 메뉴에 탭 역할이나 가짜 드롭다운 화살표를 붙이지 않는다. 패널 전환이 필요한 경우에만 키보드 동작·선택 상태를 갖춘 탭을 구현한다.

예시 헤더는 공식 웹 원본 `assets/official/gnu-web-logo.png`를 사용한다. 로고의 원본 URL과 해시는 `assets/manifest.json`에서 확인할 수 있다. `data/web.json`의 `banner_image` 기본값은 `null`이다. 사용자가 사진 배너를 명시적으로 요청한 경우에만 제공된 로컬 이미지 경로를 지정한다. 캠퍼스 항공사진을 자동으로 추가하거나 사진 위에 후크 문구를 겹쳐 넣지 않는다.

참고 화면의 청색 그라데이션은 웹의 시각적 참고 요소다. 작은 흰 글자와 배경의 대비가 부족하면 `DESIGN.md`의 대비 확보용 UI 청색 단색을 쓴다. 공식 로고의 청색은 바꾸지 않는다. 회색 메뉴도 텍스트와 테두리가 바탕에서 구분되도록 확인한다.

글자 확대·공유·인쇄 아이콘이 참고 화면에 있지만 이 도구에서는 필요한 기능만 제공한다. 화면의 원형 도구 모양을 장식용 버블로 반복하지 않고 간결한 기능 버튼으로 적용할 수 있다. 지누, 기부 캐릭터, AI 상담 캐릭터와 떠 있는 캐릭터 메뉴는 모든 웹 제작에서 제외한다.

## 폭과 반응형 적용

- 데스크톱은 공식 웹 CSS에서 관찰한 최대 본문 폭 **1565px**를 출발점으로 삼는다. 헤더와 현재 위치 띠의 배경은 화면 폭에 맞추고 안쪽 내용은 본문 기준선에 맞춘다. 작은 화면에서는 최대 폭보다 실제 화면 폭과 여백을 우선한다.
- 좌우 여백은 데스크톱 24–32px, 모바일 16px를 제안한다. 페이지 제목 아래와 메뉴·본문 사이에는 충분한 흰 여백을 유지한다.
- 좁아지면 헤더 메뉴를 줄바꿈하거나 동작하는 접힘 메뉴로 바꾼다. 세 하위 메뉴를 글자를 줄여 한 행에 강제로 넣지 않고 세로로 쌓거나 공간에 맞게 줄바꿈한다.
- 본문의 항목명·설명 두 열은 모바일에서 항목명 위, 본문 아래의 한 열로 바꾼다. 표가 넓으면 표 영역에만 가로 스크롤을 제공하고 페이지 전체는 가로로 넘치지 않게 한다.
- 제목·연락처·긴 링크가 320px 폭과 200% 확대에서 잘리지 않도록 한다. 키보드로 본문 바로가기, 메뉴, 자료 링크, 인쇄 버튼에 접근할 수 있어야 한다.
- 인쇄·읽기용 PDF에서는 조작 버튼과 배너의 장식 공간을 정리하고 실제 제목·본문·표·문의처를 읽기 쉬운 순서로 출력한다. 화면 전체 PNG에는 웹 화면의 구조를 보존한다.

## 제작물 확인

흰 헤더 → 현재 위치 띠 → 좌측 페이지 제목 → 직사각형 하위 메뉴 → 항목명·본문 행의 순서가 드러나는지 확인한다. 실제 페이지에 없는 기능·기관 전체 메뉴가 추가되지 않았는지, 로고·사진이 늘어나지 않았는지, 하위 메뉴와 인쇄가 동작하는지 점검한다. HTML·전체 화면 PNG·읽기용 PDF 세 형식을 기본으로 저장하고 실제 확인한 범위를 설명한다.
