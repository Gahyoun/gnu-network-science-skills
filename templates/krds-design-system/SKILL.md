# KRDS design system (GNU)

`DESIGN-SYSTEM.md`가 기준이다. 작업 전에 해당 장을 읽는다.

## 작업 순서

1. **범위 확인.** 화면(웹·앱)이면 이 스킬, 인쇄물이면 `gnu-template`. 확장형 스타일이므로 정부 상징·공식 배너·정부 청색은 쓰지 않는다(0장).
2. **토큰 연결.** `tokens/primitives.css`, `tokens/semantic.css`를 불러오고 `html { font-size: 62.5% }`. 화면 CSS에는 `--gk-*` 색 별칭과 `--krds-*` 크기·간격 토큰만 쓴다.
3. **구성.** 콘텐츠 최대 1200px, 분기점 360/768/1024/1280(5장). 글자는 정의된 스케일만, 본문 17px·줄 간격 1.5(3장). 래디어스는 높이 × 1/8(4장). 그림자는 떠 있는 요소에만(7장).
4. **상태와 모드.** 상태는 같은 hue에서 한 단계씩(2.4). `data-krds-mode="high-contrast"`로 바꿔 정보·기능·포커스가 그대로인지 본다(8장).
5. **검수.** 12장 점검표를 모두 확인한다. 대비는 단계 번호로 먼저 판단하고, 흰색 외 바탕은 실제로 잰다. 320px·200% 확대·키보드 이동을 확인한다.
6. **보고.** 바꾼 파일, 점검 결과, 지키지 못한 항목과 이유를 짧게 알린다.

## 지킬 것

- 공식 GNU Blue `#009EDB`(3.04:1)는 글자·흰 글자 바탕에 쓰지 않는다. 그래픽 전용 `--gk-brand`.
- 색만으로 정보를 구분하지 않는다. point(Gold)는 화면의 5% 이하.
- 밑줄은 링크에만. 비활성에 투명도를 쓰지 않는다.
- 로고는 원본 파일만, 변형하지 않는다. 내용(인명·일정·수치)은 지어내지 않고 `[입력 항목]`으로 남긴다.
- 색 단계를 바꿀 때는 `python3 scripts/build_tokens.py`를 다시 실행해 매직넘버 검사를 통과시킨다.
